# منارات · منصة متعددة المراكز (SaaS)

هذا الملف يشرح بنية المنصة، وكيف تنختبر، وشو لازم قبل ما تنزل على قاعدة بيانات حقيقية.

## قاعدة البيانات: `supabase/migrations/20261113000000_manarat_baseline.sql`

ملف أساسي واحد ينشئ البنية فقط، والمنصة تبدأ **فارغة تمامًا**: لا مراكز ولا طلاب ولا بيانات قديمة. كل مركز يُنشئه صاحبه (`create_center`)، والسور الـ114 في `20261113000100_quran_surahs.sql`. أي تعديل لاحق يكون ملف migration جديدًا بعدهما.

- **centers:** جدول المراكز. فيه الاسم، والرابط (slug)، والدولة، والمدينة، والشعار، ولوحة الألوان، والنبذة، والتواصل، والمنطقة الزمنية، واللغة، والحالة، والخطة، والنطاق الخاص.
- **memberships:** جدول العضويات (user_id, center_id, role, is_owner, active…). المستخدم الواحد ممكن يكون بأكثر من مركز.
- **app_users و profiles:** `app_users` هو هوية الشخص، و`profiles` صار view فوق عضويات المركز الحالي.
- **center_id:** عمود على كل جداول بيانات المراكز (19 جدول)، بيتعبّى لحاله من المركز الحالي للمستخدم.
- **العزل بقاعدة البيانات:**
  - كل جدول عليه سياسة RLS من نوع *RESTRICTIVE*: `center_id = المركز الحالي`. حتى لو شاشة أو استعلام نسي الفلترة، ما بيطلع صف من مركز ثاني.
  - في **trigger** بيمنع ربط سجل بسجل من مركز ثاني (طالب، حلقة، كتاب…) حتى لو انخمّن الـ id.
- **دوال SECURITY DEFINER:** كلها بتشتغل داخل المركز الحالي فقط (الحذف، والاسترجاع، وسلة المحذوفات، وطلبات التسجيل، ورابط ولي الأمر…).
- **كل مركز لبياناته فقط:** من موقع منارات أو من نطاقه الخاص (`centers.domain`) أو من التطبيق المثبّت، تُحفظ الطلاب والحلقات والسجلات لحساب ذلك المركز وحده.
- **ranking_settings:** صف لكل مركز.
- **دوال المنصة:** `my_context`, `switch_center`, `public_center`, `create_center`, `invite_info`, `accept_invite`, `super_centers`, `super_set_center`. شرحها بـ `docs/API.md`.
- **مجانية بالكامل:** لا فترة تجربة ولا حد لعدد الطلاب.
- **إشعارات Push:** جدول `push_subscriptions`، وكل شخص يرى اشتراكاته فقط.

## الصفحات

| الرابط | شو هو |
|---|---|
| `/login` | على نطاق مركز: صفحة المركز. على عنوان المنصة: صفحة منارات و«سجّل مركزك» |
| `/{slug}` | صفحة المركز العامة: الاسم، والشعار، والنبذة، والتواصل، وملاحظات إضافية |
| `/{slug}/register`, `/{slug}/honor` | نموذج تسجيل الطلاب ولوحة الشرف لكل مركز |
| `/signup` | سجّل مركزك: حساب صاحب المركز (البريد فقط) وتأكيده بكود من 6 أرقام يصل إلى البريد |
| `/onboarding` | معالج الإعداد: المركز، ثم الشعار والألوان، ثم أول حلقة وطلابها، ثم أول معلّم |
| `/invite/{token}` | قبول دعوة مدير أو معلّم |
| `/super` | لوحة إدارة المنصة: كل المراكز، والتفعيل والإيقاف، والخطة |
| الإدارة ← بيانات المركز | تعديل الاسم والنبذة والشعار والألوان والتواصل والملاحظات |
| الإدارة ← دعوة / استيراد | دعوة بالبريد أو واتساب، واستيراد طلاب من Excel أو CSV |

## الهوية البصرية

- **الواجهة الرئيسية:** كحلي وذهبي (`app/landing.css`).
- **التطبيق:** بيستخدم لوحة ألوان المركز (`app/theme.css`).
- **4 لوحات ألوان:** كحلي وذهبي (الافتراضية)، ونيلي ورملي، وعنّابي ورملي، ورمادي هادئ.
- **مكان الألوان:** كل الألوان والخطوط والمسافات متغيرات CSS بمكان واحد، والوضع الداكن تلقائي حسب الجهاز.

## الصلاحيات

| الدور | شو بيشوف وشو بيعمل |
|---|---|
| مدير المنصة (`platform_admins`) | `/super`: قائمة المراكز وأعدادها، والتفعيل والإيقاف، وتغيير الخطة. ما بيشوف بيانات المراكز اليومية |
| صاحب المركز / المدير | كل شي داخل مركزه، ودعوة مدراء ومعلّمين، والإعدادات. صاحب المركز ما بينزّل دوره ولا بينحذف |
| المعلّم | طلاب مركزه وحلقاته، والحضور والتسميع والتقييم |
| ولي الأمر | رابط خاص لكل طالب، عليه اسم المركز وشعاره |

**أمان الخادم:**
- مسارات `/api/admin/*` بتتحقق من المدير **ومن مركزه**، وما بتغيّر بريد حساب مشترك مع مركز ثاني.
- **رفع الشعار:**
  - PNG أو JPG أو WebP بس (لا SVG)، لحد 5MB.
  - بيتعاد رسمه بالمتصفح على 256px.
  - قاعدة البيانات بتتحقق من الصيغة والحجم.

## الاختبار

```bash
npm run test:db      # 116 اختبار عزل وصلاحيات على Postgres حقيقي (PGlite) بدون إنترنت
```

**شو بيعملوا الاختبارات:**
1. تبني القاعدة من ملفات `supabase/migrations` وتتأكد أنها فارغة (لا مراكز ولا طلاب).
2. تُنشئ مركزًا أول وتُدخل بياناته عبر حساب مديره (كما في الواقع).
3. تتحقق من:
   - أن كل سجل جديد يأخذ مركز المستخدم تلقائيًا.
   - إنه المركز الجديد ما بيشوف شي من غيره.
   - إنه كل محاولات الوصول بين المراكز بتفشل.
   - الدعوات.
   - المستخدم بمركزين.
   - الإيقاف.
   - الإشعارات.

**النسخة التجريبية:**
- **التشغيل:** `NEXT_PUBLIC_DEMO=1` بيشغّل Postgres داخل الموقع نفسه (`lib/demo`) بنفس ملفات الترحيل ونفس الـ RLS. تبدأ بحسابات الدخول ومركزين فارغين، ومن يجرّب يضيف حلقاته وطلابه بنفسه.
- **البيانات:** وهمية، وبتنمسح عند إعادة التشغيل.
- **حسابات التجربة** (كود الدخول `123456`):
  - `admin@demo.com`: مركز النور.
  - `doha@demo.com`: الدوحة.
  - `both@demo.com`: معلّم بالمركزين.
  - `super@demo.com`: إدارة المنصة.
- **على الموقع الحقيقي:** المسار `/sb` بيرجّع 404 دايمًا.

## قبل النشر على قاعدة حقيقية (بالترتيب)

1. **إنشاء المشروع:** مشروع Supabase خاص بمنارات، وتطبيق كل ملفات `supabase/migrations` عليه بالترتيب.
2. **إعدادات Authentication في Supabase:**
   - تفعيل **Allow new users to sign up** (ضروري لـ«سجّل مركزك» والدعوات).
   - تفعيل **Confirm email**.
   - مراجعة **Rate limits**.
   - إضافة `/auth/confirm` و`/invite/*` على نطاق المنصة إلى Redirect URLs.
3. **متغيرات Netlify:**
   - `NEXT_PUBLIC_SUPABASE_URL` و`NEXT_PUBLIC_SUPABASE_PUBLISHABLE_KEY` و`SUPABASE_SERVICE_ROLE_KEY`.
   - للإشعارات: `NEXT_PUBLIC_VAPID_PUBLIC_KEY` و`VAPID_PRIVATE_KEY` (توليدها: `npx web-push generate-vapid-keys`) و`VAPID_CONTACT`.
4. **الأنواع:** بعد النشر، تحديث `lib/supabase/database.types.ts` من Supabase.
5. **النطاق:** نطاق المنصة بينضاف بـ Netlify، وكل مركز ممكن ياخد نطاقه الخاص من `centers.domain`.

## ملاحظات

- **تبديل المركز:** بيمسح النسخة المحلية على الجهاز، بعد التأكد إنه كل التغييرات انبعتت.
- **البريد:** إرسال الدعوات بالبريد بده SMTP مضبوط بـ Supabase. إذا مش مضبوط، بيظهر رابط الدعوة للنسخ أو للإرسال بواتساب.
- **الدفع:** الخطط وحدودها موجودة، والدفع (Stripe أو بوابة محلية) لسا ما انربط.
